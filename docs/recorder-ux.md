# Recorder UX

The live recorder uses the balanced board: a compact sticky scoreboard and clock, a three-column action grid, then field/goalkeeper selection and bench. Recovery, Shot and Ball loss occupy the first row in that order, with 76px minimum phone targets and icons above labels. Foul, Card and Substitution occupy the quieter second row with 56px minimum phone targets. Fine-pointer desktop controls use horizontal icons/labels, 44px targets for both action rows, matching player and bench controls, with a 16px clock-to-action gap so a full ten-player call-up and footer fit at 1366×768. Smaller screens and enlarged text retain normal scrolling. Recovery uses a mint tint, Shot a neutral tint and Ball loss a red tint. Action buttons use translucent fills without visible borders; keyboard focus outlines remain. The same action order and hierarchy apply inside player-first and rink-first dialogs after eligibility filtering. Labels wrap and targets grow with long translations. Player, goalkeeper and bench controls retain their grouping and eligibility, using borderless translucent surfaces. Phones hide the application header/footer and show recent events below; desktop places the full timeline beside capture controls. Overflow options provide score correction, language and synchronization details. Change direction sits beside the rink on mobile and desktop.

On desktop, the recorder fills the space between the application header and footer. The left column holds the scoreboard, clock controls, compact actions and lineup. The right column holds a rink capped at 480px wide above the timeline. Only the event list scrolls within the timeline, leaving its heading visible; event count never changes the spacing between the scoreboard and recording actions. The page scrolls only when the recording controls need more height than the available space. Scores, clock and penalty indicators stay sticky with the recorder navigation; Start/Pause, clock adjustment and End half/Match scroll normally below them.

## Setup and navigation

The `/app` menu links Players, Teams and Matches. Lists provide search, a New action and reusable list items. Creation uses separate pages with labeled inputs, validation and retained input on failure.

Team details support multi-selection of existing Players, optional jersey numbers and roles. Existing membership fields are editable. Match creation chooses a Team and called-up Players, with optional date/venue. Pre-start editing preserves existing snapshot identities. Creation and pre-start detail editing configure two equal halves, with editable category-based duration defaults. Prepare match selects four field starters and one goalkeeper from grouped compact rows and uses the saved format. Legacy setup without duration links to Edit details. New configurations default to left-to-right attack direction for each half. The recorder offers two single-line direction options and can change the current half; older unknown values stay readable and select the left-to-right default in the control.

Fixed query-based details/Start/live pages work offline for available records. Setup Matches offer editing and Start; live Matches offer Resume; completed Matches show the full read-only summary at `/app/matches/view?id=…`. After local completion commits, replace the live URL with this summary URL. Old live/Start links resolve to the current lifecycle screen, without rendering a duplicate summary or an intermediate action button. Setup-only call-up edit URLs no longer open the editor after the match starts. Failed completion retains the recorder and its retry feedback.

## Draft lifetime and state

Player-first and action-first entry open the same responsive dialog and use one scoped Zustand store. The first tap captures event/operation IDs, wall-clock time, current period and any known match time. End-powerplay entry also freezes the targeted card ID. Later choices, language changes and failed-save retries retain that snapshot.

| State      | Behavior                                                                              |
| ---------- | ------------------------------------------------------------------------------------- |
| Idle       | Selecting a Player or action opens a fresh draft.                                     |
| Collecting | Each compatible choice fills missing details; completing the input starts local save. |
| Saving     | Ignore duplicate submission; prevent dismissal until the local transaction completes. |
| Failed     | Retain the exact input/IDs/time. Offer Retry or Cancel.                               |
| Saved      | Close and clear the draft after local commit; upload remains durable in the outbox.   |

Cancel, the close control and Escape discard unfinished selection. Short event-entry flows have no Back control; later choices retain capture identity and time. Outside clicks do not dismiss the dialog. Close restores trigger focus. Navigation/reload drops unfinished drafts; committed events survive. No hidden draft persists behind a closed modal.

## Selection and required details

Both entry orders use the same [eligibility matrix](domain-model.md#eligibility-and-lineup). Hide incompatible actions and players. Recovery/loss/shot exclude bench players and goalkeepers; foul requires an active player; cards include eligible bench players. Card colour, recovery subtype, loss reason and shot outcome are explicit choices. An active goalkeeper has a Save action requiring Simple or Difficult. Either choice completes recording. Historical saves without difficulty remain readable and contribute to total saves, without an unclassified entry option or breakdown. Entry without coordinates also requests recovery/loss defensive or attacking half without preselection. New-event dialogs put the captured period/countdown in the header and show a compact action icon/name context row in spatial flows from opening, replacing its primary label with the selected player and retaining action/location details. Its height stays constant so selection does not move the rink; non-spatial flows need no duplicate row. The action sits beside the player name with both vertically centred; the period stays muted and only the countdown is bold and accented. No stepper or Back control is added. Action choices reuse board icons; cards use semantic yellow, blue and red accents with text labels.

Ordinary substitution selects outgoing and incoming Players, from either participant-first direction or action-first. Save the pair as one event. Do not expose standalone player-out entry.

Follow-up lists with two to four choices use one column and at least 64px phone / 56px desktop targets. Recovery choices remain one column on phones and in the desktop split pane; action selection uses two columns in the dialog. Spatial entry uses a wider desktop dialog with the optional rink on the left and choices on the right; phones stack them vertically. Desktop event-entry dialogs keep their opening width for the entire flow and stay at a fixed top offset while their natural height grows downward, capped by available viewport height. Their content remains aligned to the top, and a wide flow retains the choice column even when a later step omits the rink. Header metadata may wrap for enlarged text and unavailable-time labels. The compact Cancel footer remains visible and is smaller than the header, with at least 44px button targets. Fullscreen dialogs apply all four safe-area insets once at their content boundary, keeping the footer above the home indicator and the header clear of the notch. Other recorder dialogs retain their natural height. Desktop player-picking rows use 44px minimum heights and 8px gaps so the regular ten-player card selection fits at 1366×768; phones retain 64px player targets. Hide the visible On rink heading when all eligible players are active, while retaining its accessible group label. Keep both headings when active and bench players are eligible. Labels wrap at word boundaries rather than breaking ordinary words. Capture identity/time, automatic saving and cancellation retain their existing behavior.

Recovery choices are ordered Loose ball, Interception, Tackle, Blocked shot, Other. Loose ball includes rebounds and second balls; its short helper states this explicitly. Tackle labels the existing duel value, and Bad pass labels intercepted-pass without rewriting historical events. Losses are ordered Bad pass, Failed individual action, Poor reception, Other. Poor reception needs no helper text and means losing an incoming pass before establishing control; no historical Other events are reclassified. Shot entry is ordered On target, Goal, Off target, Blocked; Goal remains near the top for immediate recognition. These are fixed, provisional presentation orders rather than measured usage rankings. Interception versus Tackle frequency requires an identified recorded sample and explicit counts.

Loose ball/interception use mint ball-dot/arrow-reaching-ball icons; Tackle uses a blue shield-check and Blocked shot an amber shield. Bad pass uses a coral split-direction arrow, Failed individual action a blue interrupted-route icon, Poor reception an amber crossed ball, and Other a neutral ellipsis. Summary breakdowns use the same subtype tones and include Poor reception. Shot outcomes retain mint goal, blue on-target, muted off-target and yellow blocked; cards retain their actual colours. Simple/difficult saves use mint/blue, own/opponent timeouts use mint/muted, and half/set-piece choices remain neutral. All recorder buttons are borderless; keyboard focus remains visible.

Desktop navigation and sign-out text/icons share a 13px size and compact 32px hover fills inside unchanged 44px targets. The header language flag is approximately 14×10px; language-menu flags and the phone drawer retain their existing sizing. The live timeline has no decorative watermark or heading symbol.

The touch magnifier uses a viewport-fixed portal outside scrolling and blurred containers. Prefer a 28px gap above the contact point, including near the rink's upper edge. When the visible viewport cannot fit the lens above, place it beside the contact near the viewport top instead of flipping beneath the finger. Keep an 8px viewport inset. Lens placement does not change accepted coordinates, direction conversion, draft identity/time or keyboard selection.

Known game time is captured automatically, including while paused. Substitution, Player in, blue/red card and powerplay completion require elapsed period time. When time is unknown, keep the modal open with manual remaining-time counters; legacy matches without a duration retain explicitly labelled elapsed-time entry. Optional position creates no extra mandatory step. Without rink selection, ordinary event positions stay absent. Special attempts use their fixed restart spot. Rink-first drafts offer only recovery, loss, shot, foul and card. Recovery/loss half follows the accepted selected position in both step selection and saved input; do not ask for information already supplied by that point. No accepted point or an exact halfway point retains the explicit Which half? choice. Clearing a point restores that fallback.

## Game events and set pieces

The secondary Game event control opens a responsive chooser for Opponent goal, Timeout and Set piece. Show Game event only in the header; omit the duplicated identity and visible step heading before those choices. Later steps keep their specific prompts. Opening it captures identity, period, known game time and the active goalkeeper. Opponent goal saves that goalkeeper attribution when available; later lineup changes never fill missing attribution. Timeout asks Our team or Opponent and records no player or automatic clock change.

Set piece is also a secondary option in the ordinary Shot outcome dialog. Both entry points offer Penalty and Direct free hit and reuse one canonical shot draft, player eligibility and outcomes. Ordinary shots retain their previous tap count. Rink-first entry hides Set piece throughout the flow. Changing choices retains capture time and selected shooter; failed Retry uses the exact captured input. A fresh ordinary shot resets to open-play.

Special attempts automatically use shared fixed team-relative restart spots, without a rink picker or known observer direction. Their preview/timeline labels identify the restart spot. Selecting a type writes nothing; choosing the outcome saves one shot and one possible goal. Cancel writes nothing, and latest-event Undo removes the complete attempt.

## Card and powerplay flow

- Yellow confirmation records the card and leaves lineup/powerplay unchanged.
- Blue/red at five removes an active recipient or asks which active Player should leave for a bench recipient.
- Blue/red at four requires a replacement for an active recipient, or queues the penalty without lineup changes for a bench recipient.
- The third blue warns of red exclusion before confirmation and shows that consequence in the timeline.
- Show compact blue/red outstanding-penalty indicators beside the main Match clock, with the summed remaining time of the current and queued penalties. Keep the main clock, period and running status centred within the scoreboard by reserving equal space on both sides of the clock. Queued cards remain visible and available in penalty details. Opponent cards are outside this increment.
- Near On field, show a restrained red Powerplay active label and the existing lineup count. Remove the standalone powerplay block.
- Selecting the indicator opens Correct powerplay. Adjust remaining time or set it to zero to complete the current penalty. Freeze target/time at opening and retain failed inputs for exact retry.
- Blue penalties last two minutes; direct red penalties last four. Team penalties expire by playing time, pause with the Match clock and carry across halftime. Queued penalties run sequentially. Match-clock corrections affect pending deadlines. No goal-driven expiry is automated.
- When the final penalty ends, open Player in while capacity is available. Preserve an open event/control dialog and prompt after it closes. Cancellation leaves Player in beside the lineup heading. Select an eligible bench Player without an outgoing Player; capture time when opening that picker.
- Derive automatic expiry without background event writes, preserving latest-event Undo. Historical cards without a duration require correction or explicit completion. Individual suspension restrictions remain deferred.

Each card saves its required effects atomically. Undo reverses those effects together. See [Card rules](domain-model.md#cards-and-powerplay).

## Clock, score and lifecycle

Display countdown consistently for the live clock, event dialogs and timeline using each event’s captured elapsed value and its own half duration. Use the same whole-second rounding everywhere. Missing duration/time displays unavailable time rather than an invented countdown. A positive duration is required to run the clock. Support Start/resume, Pause and manual adjustment. Render from the stored anchor rather than accumulating UI ticks. Pause at zero; do not advance periods automatically.

Clock adjustment uses remaining time when duration exists, otherwise elapsed time. Existing event timestamps never change with the clock. Player choices use the lineup at the captured game time. Saving validates the chronological history before and after that time; conflicting later actions reject the change. Both timelines show latest game time first, break equal-time ties by recording order and place explicitly untimed events after timed events in each period. Undo still targets the latest locally recorded event. End period confirms before advancing; End match confirms completion in the final period. These controls persist through the shared queue rather than uploading every display tick. Attack direction can be set for the current period without altering the clock, other periods or historical events.

The inline Change event time control has been removed. The proposed replacement is a separate Add missing event action: choose the period and event time first, then use the normal event choices with historical lineup eligibility and full-history validation. It preserves the main clock. This replacement awaits UI review and implementation; the existing required-time fallback for unknown captured times remains available.

Our goal shots and opponent-goal entry update the derived score. Score correction aligns both team scores, shows our score as plain read-only text and edits only the opponent’s current total using shared minus/plus numeric controls. It has no repeated Save heading or inline submit button; Cancel and Save use the standard dialog footer, with Save filling the remaining phone width. Save appends a signed opponent adjustment and cannot produce a negative score. Historical own-score adjustments remain readable. Clock editing reuses the numeric controls, with minute/second carry and borrow, direct typing and bounded values; only Save persists changes. No regulation foul threshold or goal-driven penalty expiry is automated. Powerplay deadlines follow the saved card duration and playing clock.

## Responsive and language behavior

Support narrow screens, long/unbroken names, enlarged text, visible keyboard focus and touch access. Use text in addition to colour for state. Both catalogs are bundled. Language selection updates the visible UI without navigation, server refresh or losing draft/clock/pending data.

Browser checks have covered 320px layouts with enlarged text. Physical-device ergonomics and a full browser-family pass are still outstanding; see [Development plan](development-plan.md).

## Position entry

Desktop retains a horizontal 2:1 rink above its timeline; mobile starts with actions and lineup. Spatial event dialogs show an optional interactive rink beside the existing choices on desktop and above them on phones. Tapping selects a point directly; hold/drag uses the offset 1.5× magnifier. There is no expansion control, Skip step or extra Save. The final event choice saves automatically, so position must be selected first.

Attack/Defence badges align with their halves above the playable boundary. Defence uses the accent and a restrained tint; Attack uses muted text and a directional arrow. Markers never sit behind text. A single-line footer combines contextual guidance with Change direction and optional Remove position. Narrow layouts use accessible icon-only controls with hover/focus tooltips. Direction previews use an unboxed arrow across the centre circle.

Rink-first entry freezes identity, period, time and direction at first valid contact. Adding or editing an optional point preserves an already captured event draft. Accept a point only on release within the rounded boundary. Place the magnifier above the finger when possible, otherwise beside the contact near the viewport top, without reserving empty space. Consume the release click so it cannot activate a subsequent choice. Outside release, cancellation, multi-touch or interrupted input discard the gesture and retain any previously accepted draft point. Keyboard arrows adjust, Shift makes finer changes and Enter accepts.

Recovery/loss half is derived from the accepted team-relative point for prompts, context and saving. Without a point or exactly halfway, ask Which half?. Clearing a point restores that fallback. Non-spatial actions remove unused coordinates. Special attempts replace them with the fixed restart spot and omit the rink. An optional point does not turn ordinary entry into rink-first entry or hide otherwise eligible actions/players.

Change direction opens the existing current-half dialog beside the rink and temporarily replaces the event dialog without nesting modals. Retain draft identity, time and canonical coordinates. Unknown legacy directions require a saved direction before selecting a point; unpositioned entry remains available. No automatic halftime direction change is introduced. Gestures and direction editing lock competing controls and defer automatic Player in prompts.

## Choice presentation

Keep complete icon/text groups left aligned. Group players by On rink and Bench, with separate jersey/name alignment and a distinct goalkeeper row/shield. Preserve eligibility rules. Shot outcomes use stable icons and semantic colours; cards retain explicit colour labels. Other is the last recovery/loss choice.

Buttons use at least 44px touch targets and more horizontal than vertical padding. Mobile main actions retain three columns; dialog action selection uses two, and short follow-up lists use one column. Clock controls reserve balanced side slots around Start/Resume/Pause. Start appears at full remaining time and Resume after elapsed time. At zero, the primary becomes Next half or End match and opens the existing confirmation. The next half stays paused. Early finish uses an icon-only checkered flag with accessible text and a tooltip.
